# MarinBox

Windows-клиент MarinVPN в духе Happ: добавляете ссылку подписки (или ключ), выбираете сервер, жмёте кнопку — трафик идёт через Xray-core, системный прокси включается сам.

## Что умеет

- Подписки по ссылке `https://…` (3x-ui и совместимые), обновление, остаток трафика и срок из заголовка `subscription-userinfo`
- Ключи `vless://` (в т.ч. Reality), `vmess://`, `trojan://`, `ss://`, по одному или списком
- Транспорты: tcp, ws, grpc, httpupgrade, xhttp, h2; TLS и Reality
- Пинг серверов, таймер сессии, сворачивание в трей
- Ссылка `marinbox://add/<ссылка подписки>` добавляет подписку в один клик
- При выходе или падении системный прокси возвращается к прежним настройкам
- **TUN-режим**: весь трафик системы (в том числе приложения, игнорирующие системный прокси) идёт в туннель
- **Пресеты маршрутизации**: Россия напрямую, блокировка рекламы/трекеров/18+, Discord, соцсети, YouTube, OpenAI напрямую
- **Обновление ядра Xray** прямо из приложения: новая версия Xray-core скачивается с GitHub и кладётся рядом, не ломая установленную сборку
- **Светлая тема** и свой цвет акцента (или «как в системе»)
- **Вход в кабинет в один клик**: кнопка «Войти через Telegram» открывает бота со ссылкой подтверждения, приложение входит само
- **Уведомления Windows**: подключение, потеря связи, восстановление, обновления
- **Автообновление приложения**: проверка новой версии при запуске, скачивание и установка

## Сборка exe (на Windows)

Нужен Node.js 20+.

```powershell
cd MarinBox
npm install
npm run fetch-xray     # скачает Xray-core в bin\ (xray.exe, geoip.dat, geosite.dat)
npm start              # проверить в режиме разработки
npm run dist           # собрать
```

Результат в `dist\`:
- `MarinBox Setup 1.0.0.exe` — установщик
- `MarinBox 1.0.0.exe` — портативная версия

Xray упаковывается внутрь приложения автоматически (папка `bin\`).

Проверки:
```powershell
npm test               # парсер, конфиг, пресеты, логика обновлений
npm run check:config   # собранные конфиги Xray (пресеты + TUN) на настоящем xray
node scripts/test-tun.js  # дымовой тест TUN: поднимает туннель в обход VPN (нужны права админа)
```
## TUN-режим

Включается в настройках («TUN-режим» → «Весь трафик через VPN»).

- Работает на родном TUN-инбаунде Xray-core: создаётся адаптер `MarinBox` (Wintun), маршруты `0.0.0.0/0` и `::/0` уходят в туннель, DNS-запросы идут через 1.1.1.1/8.8.8.8 тоже по туннелю
- WFP-фильтр включён только для `misconfigtun` (трафик версии IP без маршрутов). Фильтр `dns` намеренно выключен: он запрещает резолверу обращаться к обычным DNS-серверам и вместе с этим ломает разрешение имён, если UDP через сервер идёт медленно
- Нужны права администратора: при подключении Windows спросит разрешение (UAC). Запускается только Xray, сама MarinBox остаётся обычным процессом
- Пока включён TUN, системный прокси не включается: трафик уже весь в туннеле
- При смене режима VPN переподключается
- Маршруты и адаптер снимаются при выходе из приложения; если MarinBox упал — обёртка Xray сама завершается (она следит за родителем)

## Пресеты маршрутизации

Готовые наборы правил Xray (`lib\route-presets.js`), применяются при следующем подключении:

| Пресет | Что делает |
|---|---|
| Россия напрямую | `geosite:category-ru`, `geosite:category-gov-ru`, `geoip:ru` — мимо туннеля |
| Блокировка рекламы | `geosite:category-ads-all` → blackhole |
| Блокировка трекеров | `geosite:category-public-tracker` → blackhole |
| Блокировка 18+ | `geosite:category-porn` → blackhole |
| Discord напрямую | `geosite:discord` |
| Соцсети напрямую | ВК, ОК, Facebook, Instagram, Twitter |
| YouTube напрямую | `geosite:youtube` |
| OpenAI напрямую | `geosite:openai` |

Свои исключения (домены и CIDR) задаются в соседней карточке настроек и имеют приоритет над пресетами.

### Обновление ядра Xray

Вкладка **Xray → Ядро Xray**:

- «Проверить обновления» — сравнивается текущая версия с последним релизом [XTLS/Xray-core](https://github.com/XTLS/Xray-core/releases);
- «Обновить ядро» — архив `Xray-windows-64.zip` скачивается с GitHub, распаковывается в `%APPDATA%\MarinBox\core\v<версия>\` (xray.exe, geoip.dat, geosite.dat) и проверяется запуском;
- обновлённое ядро имеет приоритет над тем, что вшито в сборку, поэтому установленное приложение не ломается; старые версии (кроме двух последних) удаляются;
- если VPN был подключён — соединение переподключается с новым ядром.

Прав администратора не нужно: всё живёт в папке пользователя.

### Оформление

Вкладка **Приложение → Оформление**: тёмная тема, светлая или «как в системе», плюс свой цвет акцента
для кнопок и графики. Тема применяется сразу при запуске окна — без мигания.

### Разделы настроек

| Раздел | Что внутри |
|---|---|
| Приложение | автозапуск, трей, уведомления, автообновление, тема и акцент |
| VPN | надёжность (проверка, переподключение), тип пинга, TUN-режим |
| Маршрутизация | пресеты и свои исключения (домены, IP/CIDR) |
| Xray | обновление ядра, уровень журнала, открыть лог |
| О программе | обновление приложения, changelog, поддержка, сброс настроек |

## Вход в кабинет

Раньше нужно было вручную отправлять боту команду `/box 123456`. Теперь достаточно нажать
кнопку **«Войти через Telegram»** в приложении:

1. приложение просит у сервера код и открывает ссылку `https://t.me/<bot>?start=box_<код>`;
2. бот подтверждает вход по этой ссылке (одно нажатие «Открыть» в Telegram);
3. приложение опрашивает сервер раз в 2 секунды и входит само.

Ручной ввод кода остался как запасной вариант — если по ссылке не открылся Telegram.

Серверная часть: `GET /api/desktop/login/status?code=…` в `webapp_server.py`,
состояние кода — `db.desktop_login_state()`, обработка ссылки — `/start box_<код>` в `bot.py`.

## Автообновление и changelog

Источник обновлений выбирается в `package.json`:

```json
"marinbox": {
  "updateSource": "github",
  "githubRepo": "marinvpn/marinbox"
}
```

- `github` — клиент спрашивает `https://api.github.com/repos/<repo>/releases/latest`; тег релиза = версия, текст релиза = changelog, вложение `.exe` = установщик;
- `custom` — клиент спрашивает свой манифест `webapp\release.json` на вашем сервере (запасной вариант).

Переопределить без правки кода: переменные окружения `MARINBOX_UPDATE_SOURCE`, `MARINBOX_GITHUB_REPO`, `GITHUB_TOKEN`.

### Релиз через GitHub

```powershell
cd MarinBox
npm version patch            # или minor / major

# Релиз в GitHub: тег v1.0.1, описание = changelog, вложение = установщик.
# Changelog берётся из раздела CHANGELOG.md версии, если заполнить --notes-file,
# иначе из тела релиза.
$env:GITHUB_TOKEN = "ghp_..."        # токен с правом contents:write
npm run release -- --github
```

Скрипт сам:
1. собирает `dist\MarinBox Setup 1.0.1.exe`;
2. создаёт (или обновляет) релиз `v1.0.1` в репозитории: тег, название и **chelog из `CHANGELOG.md`** в описании релиза;
3. загружает установщик как вложение релиза;
4. дополнительно раскладывает установщик в `downloads\` и обновляет `webapp\release.json` — на случай, если GitHub недоступен.

Токен: GitHub → Settings → Developer settings → Personal access tokens → **Contents: Read and write**. Токен с правом только `public_repo` тоже подойдёт для публичного репозитория.

### Релиз через свой сервер (запасной путь)

```powershell
npm run release                # без --github: сборка -> downloads\ -> webapp\release.json
..\deploy\upload.ps1 -Server <ip> -User <user>
```

Манифест (`webapp\release.json`) устроен так:

```json
{
  "version": "1.0.1",
  "url": "https://marinvpn.best.mooo.com/downloads/MarinBox%20Setup%201.0.1.exe",
  "notes": "- ТUN-режим\n- Новые пресеты маршрутизации",
  "mandatory": false,
  "sha256": "…",
  "size": 94067195,
  "publishedAt": "2026-11-12"
}
```

### Что происходит у пользователя

- при запуске и раз в 6 часов клиент проверяет обновления;
- если версия новее — приходит уведомление Windows и появляется кнопка «Скачать» в настройках;
- после установки приложение перезапускается и **один раз** показывает окно «Что нового» с текстом changelog;
- если источник недоступен, changelog всё равно показывается из локального `CHANGELOG.md`, который вшит в сборку;
- в настройках всегда есть кнопка «Что нового» — можно перечитать changelog в любой момент.

## Свой стиль

- Цвета и скругления: блок `:root` в начале `renderer/style.css`
- Логотип: положите свой PNG (лучше 512×512 и больше) в `build\logo-source.png` и запустите `npm run icon`. Скрипт обрежет прозрачные поля и сам нарежет `build\icon.ico` (16…256), `build\icon.png` (окно и таскбар), `build\tray@2x.png` (трей) и `renderer\logo.png` (шапка). Мелкие размеры (до 48 px) рисуются плоским знаком — детализация 3D в таскбаре не читается, крупные берутся из вашего artwork
- Тексты интерфейса: `renderer\index.html` и `renderer/app.js`

Палитра сейчас подобрана на глаз (бирюзовый → фиолетовый на тёмно-синем). Если пришлёте реальные цвета и логотип MarinVPN, подстрою один в один.

## Ограничения первой версии

- Exe не подписан сертификатом, поэтому SmartScreen покажет предупреждение («Подробнее» → «Выполнить в любом случае»). Для публичной раздачи нужна подпись кода.
- Telegram не принимает ссылки `marinbox://` в кнопках бота. Для кнопки «Открыть в MarinBox» нужна https-страница, которая делает редирект на `marinbox://add/…`.
- Порты Xray: SOCKS 10808, HTTP 10809. Если заняты, будет ошибка при подключении (константа `PORTS` в `main.js`).
- В TUN-режиме DNS задаётся как 1.1.1.1 и 8.8.8.8: трафик к ним идёт через туннель, поэтому провайдер не может подменить ответы.
- Автообновление требует, чтобы на сервере лежал `webapp\release.json` с прямой https-ссылкой на установщик.
